# 麦麦管家小程序源码

这是参赛仓库中的可选原生微信小程序界面，使用 WXML、WXSS 和 JavaScript。参赛主入口是 [`maimai-butler` 只读 Skill](../skills/maimai-butler/SKILL.md)；小程序保留为开发源码，不进行微信正式发布，也不是可直接访问的公共云服务。

## 本地预览

1. 下载或克隆完整仓库，将根目录的 `project.config.example.json` 复制为 `project.config.json`。示例使用测试 AppID；本地配置已从 Git 排除。
2. 用微信开发者工具导入**仓库根目录**，选择“小程序”。目录可以位于任意位置，`project.config.json` 中的 `miniprogramRoot` 指向 `src/`。
3. 无正式 AppID 时按开发者工具提供的测试模式检查基础页面；真机预览、定位、微信身份和云开发能力需要自己的 AppID 与相应权限。
4. 保持 `app.js` 的 `fixtureMode: true`、`cloudEnabled: false`，可从首页进入通用快照推荐，回答或跳过问题并切换候选方案。

fixture 中的菜单、价格、营养和时间都是演示数据，不能当作当前餐厅可售清单。`backendURL` 为空时不请求本地 Python 服务；若自行配置该服务，应按微信开发环境要求配置合法地址与 HTTPS，详见 [`backend/README.md`](../backend/README.md)。

## 自行接入实时只读推荐

开发者需要准备自己的微信 AppID、CloudBase 环境、数据库与云函数配置。在本地 `project.config.json` 中填写自己的 AppID，在 `app.js` 中设置自己的 `cloudEnvId` 并启用 `cloudEnabled`；只有显式配置后才初始化云开发。仓库不附带可供公众使用的生产凭据。

`cloudfunctions/mcd-token/` 源码提供 Token 绑定与状态查询、真实门店选择、只读推荐、用户自选模型、偏好和报价等功能。Token 提交给自己部署的云函数后由服务端加密保存；前端不把凭据放入本地存储或模型提示词。完整环境设置、数据表与权限应在自己的环境中核验；历史部署记录不代表克隆项目后自动配置完成。

典型实时路径是：确认 CloudBase 用户身份 → 连接自己的麦当劳 MCP → 查询并选定营业门店 → 提交预算和偏好 → 查询该店菜单、详情与营养 → 展示来源和更新时间。查询失败时以界面提示为准，快照数据仍须标明非实时，硬约束冲突不能用不符合要求的快照掩盖。

- 真机定位、头像昵称、官方付款跳转、支付后返回和真实订单全流程，应在开发者自己的环境中分别验收。微信正式提审与发布不在本次交付范围。
