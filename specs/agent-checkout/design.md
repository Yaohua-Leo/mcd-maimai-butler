# 实现设计

## 交互与视觉

目的：用户在同一份推荐上连续调整，然后核对官方报价和订单状态。沿用已验收的麦当劳风格：金色 #FFBC0D、红色 #DB241C、奶油底 #FFF8DF、墨色 #171717，沿用项目字体 PingFang SC/Microsoft YaHei 及平台回退，不重新换肤。结果卡下增加调整输入和变更记录；我的页面增加偏好保存/停用/删除；确认页把门店、餐品和金额放在最终确认按钮之前；等待和异常继续复用独立状态页。

## 服务端边界

- `conversation.js`：结构化意图合并、局部锁定、变更摘要；模型只能返回请求补丁，规则层检查约束和餐品。
- `state-store.js`：现有 CloudBase MySQL 服务端 SDK 参数化访问。每条记录带 owner_id/_openid、版本和有效期；会话仅存必要的结构化状态，不存原始对话或密钥。偏好单独按明确同意保存。
- `checkout.js`：服务端方案→默认规格→官方报价→一次性确认→创建/查询/取消状态机。价格和订单状态不由模型生成。付款链接及订单敏感载荷使用现有 AES-GCM 加密后持久化。
- `mcp-contracts.json`：2026-10-17 实际 tools/list 发现的契约；发现不代表执行成功。calculate-price 返回分，create/query-order 金额描述为元，分别解析；takeWayCode 只能来自报价返回的 takeWayList。
- 新增 action：会话读取/选择替代方案/清除，偏好读取/保存/停用/删除，报价、确认准备、创建、订单列表/状态、付款链接读取、取消准备/确认。

## 安全与失败

所有记录查询同时约束当前身份和记录ID，客户端不得提交 owner_id、可信价格或任意订单ID驱动写操作。会话/报价版本冲突要求刷新。写调用先占用一次性确认和执行记录；重复请求返回现有状态。未知结果只读核实，不自动重发。支付链接仅从官方工具返回，限定 HTTPS 官方域名/显式配置的受信任域名；页面参数仅带内部记录ID，不携带支付URL。

默认 G2 写入开关关闭，最终人工验收时按测试用户开启；每次仍须在小程序确认。自动化只调用只读工具和报价，写工具用契约替身覆盖状态机。

## 验证

纯逻辑与状态机测试、实际 MCP 只读/算价联调、CloudBase 数据隔离和版本测试、模拟器逐页检查；最后生成一个预览码和一份人工复核清单。真实下单/付款/取消状态明确列为待人工验证。
