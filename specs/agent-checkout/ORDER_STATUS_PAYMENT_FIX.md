# 0.3.1：官方付款入口与订单状态修复

## 问题与证据

用户反馈：小程序创建的未付款订单能在官方 App 找到，但小程序没有显示付款入口；在官方 App 取消后，小程序仍显示“状态待核实”。

2026-10-17 使用本机已有凭据进行了两轮只读检查，每轮调用 `order-list` 及三次 `query-order`。三条历史订单均实际返回 `orderStatus="订单已完成"`、详情中的 `status="40"`。旧代码按文档中的数字枚举直接解析 `orderStatus`，因此中文状态落入“待核实”。已有脱敏归档还记录 `orderStatus="待支付"` 与独立的 `status="10"`；独立 `status` 数字空间不能与文档的 `orderStatus` 数字枚举混用。

本轮只输出状态标签和字段名，未输出凭据、订单号、门店、餐品、金额或付款链接。只读检查使用的是本机配置账号，不代表已远程核验朋友那一笔取消订单。

## 修改

- `checkout.js` 将明确的中文待支付、已取消、已完成等标签规范化，继续兼容文档声明的数字 `orderStatus`；未知状态、取消处理中、取消失败仍不视为已取消。独立字段 `status` 仅接受明确中文标签，不猜其数字值。
- 已保存的中文状态也可正确显示，无需迁移或直接改写历史订单。刷新到已取消时关闭付款、取消操作并清除待核实提示。
- 未知状态暂时禁用付款，但保留服务端加密付款链接供后续明确状态查询使用；明确已支付、已取消等状态仍清除该链接。此前已丢失的付款链接不会被拼接或猜造。
- 订单状态页顶部新增“打开麦当劳官方小程序”，使用用户提供的公开分享链接，调用 `wx.navigateToMiniProgram({shortLink, envVersion:'release'})`，不附带 Token、付款链接、订单参数或自动下单动作。
- 官方入口用于在“我的订单”找到已有订单。提供复制订单号、显式复制公开小程序链接的回退操作；返回后沿用 `onShow → order-refresh` 查询。跳转或返回本身不代表已付款。
- 本笔官方 H5 付款链接可用时保留次级按钮。即使旧订单没有 H5 链接，仍可打开官方小程序查看。

微信官方类型定义确认 `shortLink` 从基础库 2.18.1 支持，可由小程序菜单“复制链接”取得，并可省略 appId/path：
https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.api.d.ts

## 验证与发布

- 56 项相关测试通过：中文真实格式、外部取消只读同步、未知状态不误认取消、旧缓存显示、保留付款链接、跳转不提交订单、失败回退、用户取消跳转、返回刷新及卸载后的迟到回调。
- JS 语法、WXML/WXSS 编译通过。模拟器确认短链接 API 能力可用；使用纯展示数据检查付款入口布局，截图 `evidence/local/20261017-official-payment-entry.jpg`。
- 新解析器处理三条真实只读查询结果均为规范化状态6（已完成）。未创建、取消或支付真实订单。
- 服务端 `mcd-token` 已更新并确认 `Active`，控制面返回 ModTime=`2026-10-17 15:03:59`。
- 朋友已在原有0.3.0订单页点击刷新，用户回报“已显示已取消”；这是真机人工反馈，与本机只读接口检查分别记录。
- 前端版本 `0.3.1`：用户完成开发工具原生确认后，原上传任务 `confirmation_upload_1153b197-73e5-4dc5-8d63-06fca85f10b5` 返回 `status=success`、`execution_success`、`success=true`，包大小137372 bytes。未重复上传。需在微信后台确认体验版本为0.3.1；官方小程序跳转仍待新版真机验证。
- 交付文件凭据扫描60项通过，无发现；不会把进入官方小程序或返回当成付款成功。
