# 真实订单人工验收

上一版已获用户反馈人工验收无误，现已进入真实订单测试阶段。当前登录账号已开放真实入口：单笔上限100元，有效至2026-10-24 08:39（Asia/Tashkent）；其他账号默认关闭。每笔仍需单独确认，代码/模拟通过不代表真实订单G2已通过。

## 开启前

- 使用本人的真实麦当劳账号、有效 Token 和准备实际消费的营业餐厅。不要在聊天、文档、截图或日志提供 Token、付款链接、取餐柜密码或完整身份标识。
- 不需要自行改写加密密钥或环境变量。权限保存在仅管理员可访问的 `maimai_order_access` 表；以平台身份SHA-256匹配，含启用状态、金额上限和有效期。小程序只读自己的权限，没有自行授权入口。
- 管理员可将该账号授权记录 `enabled` 设为0立即停止后续写入；过期自动停止允许新写入。紧急情况下，保留原环境变量并将 `MCD_ORDER_WRITE_ENABLED=false` 可关闭全部写入。旧的环境白名单配置仍兼容，但仅配置 `true` 不会向所有账号放开。不要覆盖原加密密钥。
- 官方支付 H5 还受小程序业务域名、主体资质、官方页面兼容性和微信政策限制；需要真机确认。仅接受官方 MCP 返回的 HTTPS 链接和受信任域名。若官方实际返回其他域名，先核实归属，再通过 `MCD_PAYMENT_HOSTS` 显式添加准确域名；不得使用通配符或关闭 URL 校验。

## 每笔创建

1. 用真实方案进入确认清单，核对门店、餐品、默认规格、数量、总价及取餐方式。
2. 点击创建后，核对一次性确认弹窗再点“确认下单”。如价格变化，重新核对新报价，不自动接受新价格。
3. 如果显示“提交待核实”，只刷新查询或到官方 App 核实，绝不重新发创建请求或手动清除锁后重发。模型没有写工具入口。返回一个匹配订单仅构成候选，需要人工确认关联；若没有唯一候选，保留未知状态，人工在官方端核实。
4. 同一份方案再次算价后重复提交，应返回已有订单；再下一餐从新会话开始。创建请求未知时，账号级锁会阻止新创建，不能靠换会话绕过。

## 付款与取消

- 到官方付款页由本人完成付款；无法打开时，可点“复制官方付款链接”后在浏览器打开，或在麦当劳官方 App 查找订单并付款。复制前会重新查询待付款状态与付款截止时间，链接不写本地存储或页面参数。麦麦管家不收取餐费，也不自动点击付款。
- 返回订单页刷新，只有官方 `query-order` 状态 2/10 等能表示已进入配餐，打开或关闭支付页不代表成功。
- 本版取消入口仅用于官方查询仍为待付款的订单。每次选原因、确认具体订单后才调用 `cancel-order`；已付款等状态请使用官方渠道。
- `cancelResult=true` 只显示“请求已受理”，再次查询状态 7 才显示“已取消”；网络结果未知时不重发。退款能力和已付款取消不在本次范围。
